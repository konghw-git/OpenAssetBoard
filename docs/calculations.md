# 计算规则

所有出现在屏幕上的数字都由 `domain/` 里的纯函数算出，`data/` 只负责校验与事务。本文记录这些规则本身，方便对照代码与测试。

相关代码：`domain/Ledger.kt`、`domain/NetWorthTrend.kt`、`domain/Rules.kt`、`data/LedgerRepository.kt`
对应测试：`LedgerTest`、`NetWorthTrendTest`、`RepositoryTest`、`RegressionTest`

## 金额

- 内部一律用 **Long 存分**，不出现浮点。`Money.parse` / `Money.format` 是边界上唯一的字符串 ↔ 分值转换。
- 展示保留两位小数；图表坐标轴的「万」单位也在这一层处理。

## 余额

对账户 `a`、时刻 `t`：

```
balance(a, t) = 最近一条 at ≤ t 的估值.value
              + 该估值之后、t 之前（含 t）的流水对 a 的增量之和
```

- 同一时刻既有估值又有流水时，**流水视为已包含在估值里**，不再叠加。这是「盘点时填的余额就是真实余额」的直接推论。
- 账户在第一条估值之前不存在，`balanceAt` 返回 `null`，界面据此显示为「—」而不是 0。
- 补录历史估值会改变其后、下一次估值之前的余额；下一次估值之后不受影响。这是「余额由估值锚定」的必然结果，也是可编辑历史记录的代价与收益。

## 流水对余额的影响

```
flowDelta(flow, account) =
    转入 account： + (amount − fee)
    转出 account： − amount
```

手续费在「转入侧」扣除，转出侧只扣 `amount`。这样两个账户都记上之后，手续费不会被算两次。

## 净投入与累计盈亏

投资账户的净投入（net invested）：

```
netInvested(a, t) = 期初成本（baselineCost）
                  + 期初之后所有流水中对 a 的 contribution
```

其中 `contribution` 与 `flowDelta` 只在手续费的归属上有区别（`Ledger.contribution`）：

| 承担方 | 转入账户 | 转出账户 |
|---|---|---|
| `feeOn = TO` | `+ amount` | `− amount` |
| `feeOn = FROM` | `+ (amount − fee)` | `− amount + fee` |

余额那边，手续费永远从转入侧扣走；净投入这边，手续费由承担方**在盈亏里吃掉一次**：

- `feeOn = TO`、申购 10,000、手续费 15 → 转出账户 −10,000；转入账户余额 +9,985、净投入 +10,000，于是立即有 −15 的浮亏。
- `feeOn = FROM`、A → B 转 100、手续费 1 → A 余额 −100、净投入 −99（盈亏 −1）；B 余额 +99、净投入 +99（盈亏 0）。合计 −1。

累计盈亏：

```
pnl(a, t) = balance(a, t) − netInvested(a, t)
```

由此得到几个反直觉但正确的结论：

| 场景 | 结果 |
|---|---|
| 投入 100，涨到 120 后全部赎回 | 市值 0，净投入 −20，累计盈亏 +20 |
| 建账市值 12,000、期初成本 10,000 | 累计盈亏 +2,000 |
| 现金分红 300 到银行卡，下次估值市值降 300 | 基金累计盈亏不变，钱体现在银行卡的余额上 |

净投入为 0 或负数时不显示收益率——分母没有意义。这也正是 MVP 只做「累计盈亏 + 净投入」、不做收益率的原因；收益率（XIRR）在路线图里。

## 净值趋势

- **只在盘点时产生点**。没有盘点就没有新点，曲线是阶梯而不是随余额实时变化的折线。这保证了「净值曲线」等于「每次盘点时的真实净资产」。
- 期间涨跌 = 期末点 − 期初点；涨跌幅 = 差 / 期初的绝对值。
- 资产与负债的柱状图取**最近一次盘点**的各账户余额，折线是两者相减的净资产。
- 直线连接相邻两个点，不做插值或平滑：中间的波动本来就没有数据。

## 约束

Room 注解表达不了的规则集中在 `Rules.kt`，由仓储层在每次写入前检查，违反时抛出 `LedgerException`，消息直接展示给用户：

- 金额 > 0；手续费在 `[0, amount]` 内。
- 转出、转入至少有一个，且不能是同一个账户。
- 流水时间必须晚于相关账户的期初；否则会被期初估值静默吞掉，所以直接拒绝，并提示「先前移期初」。
- 估值时间不早于账户期初。
- 有记录的账户不能删除，只能停用。
- 停用账户不写估值、不计入净资产，历史净值点保持不变。

## 可验证性

上面每一条都有对应的纯函数测试。`LedgerTest` 固化了需求里列的 15 个用例（余额、净投入、手续费归属、分红、补录、删除、停用等），`RegressionTest` 覆盖后续修复过的边界。这些测试全部在 JVM 上运行，不需要设备或模拟器。
