# 健康资产

把体重、体脂率、BMI 当作一项资产来记：像盘点账户一样定期称重，像看净值曲线一样看变化。

相关代码：`domain/health/Health.kt`、`domain/health/HealthTrend.kt`、`domain/health/Energy.kt`、`data/HealthRepository.kt`、`data/FoodRepository.kt`、`ui/health/`
对应测试：`HealthTest`、`HealthTrendTest`、`EnergyTest`、`HealthRepositoryTest`、`FoodRepositoryTest`、`MigrationTest`、`RestoreTest`

## 记什么

| 指标 | 必填 | 存储 |
|---|---|---|
| 体重 | 是 | `weight_g`，克（92100 = 92.1 kg） |
| 体脂率 | 否 | `body_fat_bp`，万分之一（2580 = 25.80%），没称就是 `null` |
| 备注 | 否 | `note` |

和金额一样用整数，备份里不会出现 `92.10000000000001`。BMI、脂肪量、去脂体重都**不落库**，每次从体重、体脂率和档案里的身高现算；改身高会重算全部历史 BMI。

档案（性别、生日、身高、目标体重）是用户数据，存在 `health_profile` 单行表里，跟着备份走——不放进 `SettingsStore`，那里是不备份的设备设置。

## 一天一条

- `body_measurements.date` 唯一，以用户选的日期为准；`measured_at` 只用于显示时刻。补录历史日期时 `measured_at` 取那一天的 23:59:59。
- 保存到一个已有记录的日期，仓库抛 `SameDayExists`，界面先确认，确认后带 `overwrite = true` 再存：**复用那一天原有的行 id**，否则新 id 会撞上唯一索引。编辑一条记录并把日期改到另一条占用的日子，走同一条分支，被编辑的那一行随之删除。
- 校验：体重 20–300 kg，体脂率为空或 3%–70%，日期不晚于今天。

## 没称的日子

**把没数据当作一种正常状态，而不是一种错误。**

- 没称就没有这一行，不补 0、不插值、不前向填充。
- 曲线的横轴是真实时间，十天没称就是一段长线段；7 天平均在那里断开。
- 摘要只说覆盖率（「近 30 天 · 8 次记录」），不做连续打卡；超过 7 天没记只陈述，不催促。
- 「较上次」与上一条记录比，不要求是昨天，旁边写上一条的日期。

## 区间与起点

`HealthTrend.period` 与 `NetWorthTrend.period` 同构：

- 区间前有记录：最后一条前置记录作为起点（anchored）。
- 区间前没有记录、或选「全部」：区间内第一条作为起点。
- 区间内没有新记录：只剩一条，变化量为空，显示「新记录不足，无法比较」。

体重变化用 kg，体脂变化用**百分点**（25.8% → 24.9% 是 −0.9 个百分点）。

## 7 天平均

滚动窗口：每个有记录的日子，取它往前 7 个日历日（含当天）里的记录求平均。窗口里少于 2 条、或当天没有该指标（如体脂率为空）就没有点。相邻两个平均点相隔不到 7 天时连成一段，否则断开；只有一个点的段丢弃。每一段在图上是一条独立的虚线，缺口两边不会被连起来。

## 分级

所有区间左闭右开。

**BMI**（WS/T 428-2013 的阈值，标签用体脂秤的说法）：`< 18.5` 偏低，`[18.5, 24)` 标准，`[24, 28)` 偏高，`≥ 28` 肥胖。

**体脂率**按性别与**测量当天的周岁**分级，来自 Gallagher et al. 2000（AJCN 72(3):694–701），最低年龄段从 20 岁向下延伸到 18 岁：

| 性别 | 年龄 | 标准区间 |
|---|---|---|
| 男 | 18–39 | 8%–20% |
| 男 | 40–59 | 11%–22% |
| 男 | 60+ | 13%–25% |
| 女 | 18–39 | 21%–33% |
| 女 | 40–59 | 23%–34% |
| 女 | 60+ | 24%–36% |

低于区间为偏低，达到上界为偏高。**18 岁以下不分级**：不显示标签，但记录和备份照常保存，生日不会让恢复失败。

**身体类型**：BMI 两刀（18.5 / 24）× 体脂率两刀（10% / 20%），九格各有名字。没有体脂率的那天不落点。

**目标体重**：档案里填了就用它，否则取 BMI 22 对应的体重。健康区间是 BMI 18.5–24 对应的体重。目标进度 = (起点 − 当前) / (起点 − 目标)，起点等于目标或越过了目标时不显示百分比。

## 颜色

体重下降是好事，但「红涨绿跌」是股票的语义。健康页的变化只用中性色加箭头，不用涨跌色。饮食的缺口同理：用「缺口」「超出消耗」两个词，不用颜色。

## 饮食与热量

只是手动记录，方便自己对照热量缺口；不设目标、不给建议、不打卡。

**记什么**：`food_entries` 一行是吃的一样东西，一天任意条。按用户输入的样子存：

| 字段 | 存储 |
|---|---|
| 包装的份量 `per` | 整数 g 或 ml（「每 100 ml」是 100）；按份数记时是 2；只填一份热量时为 `null` |
| 吃了多少 `amount`、单位 `unit` | 与 `per` 同时有或同时没有；按份数记时 `unit` 是 `SERVING`，`amount` 是吃了几个半份（2 份 = 4） |
| 能量 `energy_cal` | 每份（或整份）的能量，单位 cal = 1/1000 kcal：40870 = 40.87 kcal |
| `in_kj` | 包装写的是 kJ；只决定编辑时怎么显示 |
| 蛋白质、脂肪、碳水、钠 | mg，没填为 `null` |

吃了多少对应的热量、营养素**不落库**，每次由 `Energy.scaled` 现算：值 × 吃了多少 ÷ 每份，四舍五入。1 kcal = 4.184 kJ（GB 28050 的换算）。

例：每 100 ml 171 kJ、蛋白质 0.6 g、脂肪 1.6 g、碳水 6.0 g、钠 40 mg，喝了 500 ml → 171 kJ = 40.87 kcal/100 ml，共 204 kcal，蛋白质 3 g、脂肪 8 g、碳水 30 g、钠 200 mg。

- **只有热量是必填的。** 大多数食物没有包装，记录框默认是「填热量」：估个大概的 kcal 就能保存，蛋白质、脂肪、碳水、钠收在可以展开、收起的「营养素」里。「按包装换算」时多填每份的量和吃了多少，营养素同样可选。
- **份数**：「填热量」下有「吃了几份」，− / + 一次一份，一份以下是半份。热量和营养素都按一份填，合计乘份数（水煮蛋每个 70 kcal，吃 2 个是 140 kcal）。份数以半份为单位存，所以 0.5 份也是整数；只吃一份时不记份数，和之前的记录一样。
- **能量留空**且三种营养素都填了，按 4/9/4（kcal/g）估算。
- 能量和营养素都填了、两者相差超过 15% 且超过 10 kcal 时，提示核对（最常见的是把 kJ 当成 kcal）。
- **最近吃过**：按名称去重、最近的在前，点一下把这一条的全部数字填进表单，光标落在「吃了多少」。
- 校验：日期不晚于今天；每份 1–10000，吃了多少 1–100000，份数 0.5–99；一条合计不超过 20000 kcal，单项营养素不超过 5 kg；名称最多 40 字。

**每天消耗**：Mifflin-St Jeor 公式算基础代谢（男 10·kg + 6.25·cm − 5·岁 + 5，女 … − 161），乘 1.2 估算不运动时的日常消耗。不设活动量。体重取当天或之前最近的一次称重，那天之前没称过就用第一次；年龄按当天的周岁。没有档案、没有称重或不满 18 岁时不估算，只显示摄入。

**缺口** = 日常消耗 − 当天摄入。今天还没过完，标「截至现在」；近 7 天的平均缺口只算今天之前、有记录且能估算消耗的日子，没记的日子不算 0。

## 不做

不复现体脂秤的阻抗算法（身体年龄、内脏脂肪、得分），不对接小米运动健康，不给医疗建议。饮食只记录、只换算，不做食物库、扫码、餐次和热量目标。
